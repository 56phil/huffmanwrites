# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Hugo static site (`huffmanwrites`) using the [PaperMod](https://github.com/adityatelange/hugo-PaperMod) theme. Domain: `huffmanwrites.org` (CNAME committed at `static/CNAME`). Deployed to GitHub Pages via `.github/workflows/hugo.yml` on push to `main`.

The site is a personal publication platform for Philip Huffman — books on Stoicism, civics, and neurodivergence (`/books/` is the authoritative list; one title is announced but not yet released), a weekly digest, a long-form essay section, a civics / Constitution series, and a growing library of book summaries. The site embodies the credo **"Think clearly. Live intentionally. Love deeply."** which appears on the home page, book detail pages, and the footer.

Visual identity (locked): Parian marble textures, deep midnight navy backgrounds (`#131E39`), glowing gold accents (accent color is deep amber `#D4820A`), dramatic cinematic lighting, conceptual/metaphorical imagery (not literal). Established in `skills/hero-image-workflow.md`.

## Common Commands

```bash
# Build the site (production)
hugo --gc --minify

# Build with a specific baseURL (e.g. for local preview)
hugo server --buildDrafts

# Clean rebuild (clears resources/_gen and removes stale fingerprints)
hugo --gc --minify
```

Hugo v0.167.0+extended is installed via Homebrew at `/opt/homebrew/bin/hugo`, and the CI workflow (`.github/workflows/hugo.yml`) pins the same version in its `HUGO_VERSION` env — the extended variant is required for Dart Sass and image processing. **Keep these two in step:** a build that differs between the local toolchain and production is the kind of difference that surprises you once, in production. Read the installed version with `hugo version` rather than trusting this line, which said 0.166.0 for the ten days after the local toolchain moved on 2026-09-28; a version written into prose is a version that drifts, and that is why the CI env var and this sentence are changed together or not at all.

The gates in `scripts/` have a test suite: `python3 scripts/test_gates.py`, which tests the RULES the gates enforce — the exemption logic, the fabrication patterns this corpus has produced, and the blind spots that were actually fixed. Its count is printed by that command; do not write it here, where it will drift (it said 293 on 2026-10-08 while the suite ran 308). CI runs it before the build. Beyond that there is no package.json and no linter; a clean `hugo --gc --minify` plus the gates is the check.

**A gate that inspects nothing reports OK, so coverage is part of every gate.** Each `scripts/check-*.py` ends with `coverage: <N> <unit>` — the count of items it *inspected*, not the count it flagged — and `TestGateCoverage` runs the offline gates against the real corpus and fails when a count drops below a recorded floor. This exists because `check-quotes.py --online` once scanned a published report as "0 attributions" and verified nothing while every gate said OK. A collapsing count means a selector broke (a glob stopped matching, a path moved, a parser stopped recognising the shape), which is invisible in every other way.

**The corpus-wide online gate set lives once, in `scripts/corpus-gates.sh`.** `weekly-integrity-check.sh` sources it and runs it; `TestCorpusGateWiring` asserts the job runs that list rather than its own copy, and that no `scripts/check-*.py` is orphaned — invoked by CI, a runner, or another script. Two copies of this list drifted once already: `check-quote-names.py --online` joined the publishing set on 2026-10-04 and never reached the weekly sweep, so the quoted-name-detail rule guarded only the articles it was written during. A rule that lives in one runner and not another holds only where it was written.

Credentials have exactly one home: the **login keychain** (a `huffmanwrites-*` generic password), with `~/.secrets` (chmod 600) as the fallback every launchd runner reads. `scripts/check-secrets.py` enforces that. Offline it fails if two homes disagree or a listed repo-local copy reappears. With `--online` it also asks each provider whether the resolved key authenticates: fal.ai gets a GET on a request id that cannot exist (`404` = live, `401` = stale) and SendFox gets a GET on `/lists` (`200` = live, `401` = stale). Neither submits a generation or sends a campaign, so both cost nothing. It runs in CI (where it no-ops: no keychain) and in `scripts/corpus-gates.sh`, the shared corpus gate list that `weekly-integrity-check.sh` sources and runs. The gate exists because the fal.ai key lived in three places on 2026-09-24 and only one worked, and nothing could see it: a stale key has the right length, right prefix, and right home, and is wrong only in a way you learn by spending it. **The offline half alone cannot catch the worst case**, and 2026-10-02 proved it again on SendFox: the keychain item and `~/.secrets` held *the same stale value* and agreed with each other, so a homes-comparison called it clean while a gitignored `.sendfox_token` did the work. The rule that catches the real defect is not "the homes agree" but "the resolved key authenticates" — which is why the provider probes exist and why every credential that can be probed now is. **Do not add a repo-local key file** — `.fal_token` and `.sendfox_token` were both that mistake; they are listed as legacy repo files and read the keychain.

## Architecture

### Content tree (`content/`)

- `content/_index.md` — the **mission** page (this is not the home page; the home page is rendered by `layouts/index.html`).
- `content/books/<slug>/index.md` — one directory per book. Required frontmatter: `title`, `subtitle`, `image`, `image_desktop`, `image_mobile`, `image_alt`, `hero_caption` (for hero), `image_caption` (for cover — never the same), `link` (Amazon), `lastmod`.
- `content/posts/` — section-based posts. Sub-sections:
  - `civics/` — Constitution / civics essays (First Amendment is the only full-length one; others are tiered explainers).
  - `essays/` — long-form essays and observations.
  - `stoicism/` — Stoic reflections.
  - `investing/` — investing & risk.
  - `digests/` — weekly/monthly digests (frontmatter includes `sendfox_subject` for newsletter sends).
  - `summaries/` — book summaries; the canonical structure is in `content/posts/summaries/_index.md`. Each summary uses `sort_key` (LC: "Last, First") for ordering. Summaries paginate at 6/page via `layouts/posts/summaries/list.html`.
  - `sports/` — the Kansas City Chiefs weekly report, published automatically every Tuesday in season by `com.huffmanwrites.chiefs-weekly-report`. Written and published by a scheduled job without a human review step (`sitrep/` is the other); see `skills/chiefs-weekly-report.md` for the writer's brief and the "Scheduled jobs" section below for the runner's contract. Posts carry `featuredOnHome: true` because more than five flagged posts already exist and an unflagged post never reaches the home feed.

Daily rather than weekly, so the section index cascades `hiddenInHomeList: true` — seven installments a week would otherwise occupy all five Recent Posts slots — and `layouts/index.html` surfaces the current edition in its own block instead, selecting on the same `featuredOnHome: true` flag the frontmatter gate requires. See `skills/daily-sitrep.md` and the "Scheduled jobs" section below.

### Images

- `assets/img/books/` — book covers (source images; the layouts render them as WebP via `resources.Get` + `Resize`). **This is the only home for a cover, and it is the only home that works:** every book layout reads the file through `resources.Get`, which sees `assets/` and not `static/`. There was a second copy of some covers under `static/img/books/` until 2026-10-08, and one of them (`unstuck.jpg`) had *different bytes* from the canonical file, so the site served art the build never rendered. Removed; `scripts/check-hero-paths.py` now fails on a cover that reaches only `static/`, and on a cover duplicated in both homes with different bytes. The same gate resolves `hero`, `hero_desktop`, `hero_mobile`, `image`, `image_desktop` and `image_mobile` against both homes, because a path that names no file anywhere renders an empty box on a page that still returns 200.
- `static/img/articles/` — article/newsletter hero images. Convention: `[NN]-[slug]_16x9.webp` and `[NN]-[slug]_4x5.webp` (NN = post ID, paired as desktop/mobile). Every one of these also exists, byte-identical, under `assets/img/articles/`, and **that duplication is deliberate:** the pipeline that processes an image (`partials/img.html`, the book shortcodes) reads `assets/` through `resources.Get`, while `layouts/challenge/list.html` and `layouts/podcast/list.html` emit `<img src="{{ .Params.image }}">` verbatim, which only `static/` serves. Philip, 2026-10-08: "We'll keep the duplications, for now." So `scripts/check-hero-paths.py` resolves `image` and `hero*` against both homes and reports only the cases that matter (a path that resolves nowhere, a book cover that misses `assets/`, a cover whose two copies differ) — **do not "deduplicate" this without changing those two layouts first, and do not add a gate that fails it.**
- `static/og-default.png` — default OG image for pages without `cover.image`.
- **An image URL in `og:image` or in the Book schema must be one the site actually serves.** A path under `assets/` is published only when a template resolves it as a resource, and the raw path was emitted for years: measured 2026-10-08, seven of the nine book pages carried an `og:image` and a schema `image` that returned **404**, so every link preview for those books was blank. Both partials (`layouts/partials/templates/opengraph.html`, `schema_json.html`) now prefer a file served from `static/`, and otherwise resolve the asset and use its published URL.

Use `scripts/split-session-state.py`, which is repeatable: `--keep-months N` (default 3) keeps the last N calendar months in the live file and the boundary advances by itself, so no future split needs an edit first. Dry-run by default; `--write` moves the sections; `--as-of YYYY-MM-DD` previews a later split. Three invariants it enforces, each a bug that was real or latent:
  - **The archive is appended to, never rewritten.** The first version of this script built the archive from only the sections it was moving that run. That was survivable exactly once, because the archive was empty; a second run would have replaced a 1,106-line, 120-section archive with the 25 lines of its own header. The script now reads the existing archive and adds to it, and refuses to write if any line already in it would disappear.
  - **The safety check covers both files.** It used to compare the live file's lines against the two outputs, which answers "did I keep what I am writing" and is structurally blind to "did I destroy what was already there". Both directions are checked now.
  - **A run is idempotent.** The pointer to the archive is replaced, not appended — the first version added one every run, so two runs left three `**History.**` blocks in the preamble. The pointer is recognised by shape (a blockquote leading with `**History.**`), not by its wording, because the wording names the boundary and therefore changes; a preamble blockquote that merely mentions history is not touched.
  - After a split, the reference sections (Project Overview, Pending / Next Actions, Architecture Notes, Visual Identity, Content Inventory, User Preferences, Environment Notes, FLAGGED) and `Last Updated` always stay in the live file; everything older than the window moves. Nothing is deleted, and no entry is edited.
- `SESSION_STATE_ARCHIVE.md` — every entry older than the live file's window, moved out verbatim (first split 2026-09-20, when the combined file reached 2,023 lines; reading it at session start meant reading three months of history to reach the current entry). Nothing was deleted. **Search it with `grep` when you need an earlier decision, commit hash, or rationale** — it is complete, and it is the only place those answers live.

## Conventions

- **Tone:** Personal stakes + historical context + contemporary urgency. Not yelling, not lecturing. Think *with* the reader.
- **Every Stoic Saturday digest carries a brief summary of the most recent weekly reports, each linked to its full report.** Added 2026-10-03 as a standing structural element: the reader gets the week's reports in the letter, not a bare schedule of them. For each publishing series, summarize the **most recent published installment** in a sentence or two and link it. The series and the URL shapes they resolve to:
  - **Senate Race Report** — `content/posts/essays/senate-race-report-<DATE>.md` → `/posts/essays/senate-race-report-<DATE>/` (Sundays 07:00 CT, through 2026-11-01).
  - **Docket Report** — `content/posts/essays/docket-report-<DATE>.md` → `/posts/essays/docket-report-<DATE>/` (Saturdays 08:00 CT, from 2026-10-03).
  - **Ninety-Days Report** — two monthly installments, `content/posts/investing/bond-market-ninety-days-<DATE>.md` and `content/posts/investing/sp500-next-ninety-days-<DATE>.md` (the 1st of each month).
  - **Chiefs Report** — `content/posts/sports/chiefs-report-<DATE>.md` → `/posts/sports/chiefs-report-<DATE>/` (Tuesdays 18:30 CT, in season).
  - **Global SITREP** — `content/posts/sitrep/sitrep-<DATE>.md` → `/posts/sitrep/sitrep-<DATE>/` (every morning, from 2026-10-07). The most recent edition is what the letter names; a daily series needs no cadence line, and the section index at `/posts/sitrep/` is where the rest of the week lives.
  - The **Repair Plan** is a quarterly working document for a future administration, not a reader-facing report, and is not included.
  Every summary and link must name a report that actually exists (fetch the URL and confirm it resolves before writing it in, per the URL rules below; when a series has not yet published its first installment, say so rather than linking a nonexistent page). A summary states what the latest installment found — not the cadence, which the reader already knows — so the letter reports the reports rather than advertising them. The 2026-09-25 issue's `**The weekly reports**` section is the predecessor (it named the cadences only); this supersedes it.
- **First Amendment** content gets full essay length; narrower amendments get shorter explainers.
- **`hero_caption`** is for the hero image; **`image_caption`** is for the book cover. Never mix them.
- **New hero images** must be WebP. Use the `[NN]-[slug]_16x9.webp` / `_4x5.webp` naming convention.
- **Book summaries** must include `sort_key` frontmatter (LC order: "Last, First") so the list template's `ByParam "sort_key"` keeps them in order. Established format: Executive Summary, 5 Core Arguments (numbered), thematic section, A Respectful Disagreement, Bottom Line, closing quote, `*PRH | [huffmanwrites.org] | © Philip Huffman*` attribution. Tone: positive, yet critical.
- **All Hugo posts** should have `lastmod` frontmatter (git-based date is fine). **Both of these, and the book page fields, are enforced by `scripts/check-content-frontmatter.py`** (in CI on every push, and corpus-wide in the publishing tail, because a job that pushes must not learn about a missing `lastmod` from a failed deploy): `lastmod` on every post, `sort_key` on every summary, the ten fields `layouts/books/single.html` reads on every book page, and `hero_caption` ≠ `image_caption` on a book. Hugo does not fail on an absent field — it renders a blank spot or an unintended default — so without this gate a missing `sort_key` silently misorders the summary hub. Two fields carry a documented exception: `link` only on a released book (an unreleased page has no purchase URL), and `subtitle` may be absent but never blank (`The Stoic Citizen` has no subtitle; its own cover configuration sets `subtitle: ''`).
- **The home page feed shows only `featuredOnHome: true` posts.** More than five posts carry that flag today, so an unflagged post never appears in Recent Posts at all; it is published and unseen. Any post that is meant to be discoverable from the home page needs the flag. (The summaries section is excluded the other way: its `_index.md` cascades `hiddenInHomeList: true` so book summaries stay in their own hub.) **Enforced for recurring series by `scripts/check-series-posts.py`**, which derives the series from `data/gallery.yml`'s `latest` globs and fails CI when a published installment is unflagged. It exists because the Senate race report's skill omitted the field from its frontmatter list: five installments published between 2026-09-06 and 2026-09-27 without ever reaching the home feed, and nothing could see it, since the build passed and every page returned 200. The gate takes `--file` for a draft (which the corpus scan skips), and both report runners pass it the file they just wrote.
- **All post images** lazy-load except hero images, which use `loading="eager" fetchpriority="high"`.
- **Never end a sentence with a preposition.** Established 2026-09-25 as a standing writing rule. "Who did you give it to?" becomes "To whom did you give it?"; "the man I was talking about" becomes "the man about whom I was talking"; "the house I live in" becomes "the house in which I live." This is a house style, not a claim about English usage: stranding a preposition is idiomatic and often better in speech, and the rule is adopted anyway because the site's register is formal and the discipline of restructuring the sentence tends to produce a tighter one. The rule covers body prose and frontmatter display fields alike (`title`, `description`, `hero_caption`), since a stranded preposition in a `description` is the summary a reader sees in a search result. Two exemptions, for the same reason the em-dash rule has them: (1) **inside quotation marks** — a quotation's grammar belongs to its author, and rewriting it would corrupt the quotation the citation gate exists to protect; (2) **inside a link, a code span, or a URL**, where the words are not prose. Enforced by `scripts/check-prepositions.py` (`--file <path>`, `--list` for the corpus, `--check` for the baseline ratchet, which runs in CI); pre-rule occurrences in existing files are recorded in `scripts/preposition-baseline.txt` and may be reduced freely but must not grow.
- **Copyedit + fact check every piece of content before it is committed.** Copyedit: spelling, grammar, punctuation, flow, the preposition rule above, and the em-dash limit (**no more than 3 in the prose you write**; prefer commas, colons, semicolons, or splitting sentences). Two categories are **not counted** against that limit, because they are not the editor's prose: (1) an em-dash **inside quotation marks** — a quotation's internal punctuation belongs to its author or translator, and rewriting it to save a mark would corrupt the quotation the citation gate exists to protect (the Thiel "franchise to women — two constituencies… libertarians —" line is the model case, and the same exemption covers a quoted title or description in frontmatter); (2) an em-dash standing as a **date or numeric range**. That second exemption is a guard rather than a licence: the **en-dash** (`–`) is the correct mark for a range (`1903–1977`, `Aug 25–31`, `53–47`), which is what the site already uses, so an em-dash between dates is a typo to fix rather than a dash to keep. Count with `python3 scripts/check-emdashes.py` (`--file <path>`, `--list` for the corpus, `--check` for the baseline ratchet). Fact check: every load-bearing claim (dates, names, figures, attributions) verified against a source; correct or flag anything unverifiable before publishing. This gate applies to essays, digests, summaries, and any other content.
- **Quotations from translated works must name the translator, the translation, and the year.** "Marcus Aurelius, *Meditations*, 6.21" is an incomplete citation: it credits the author and hides the translation, and the translation determines every word inside the quotation marks. Renderings diverge materially — 6.21 reads "convince or shew me… gladly change" (Chrystal, 1902), "prove and bring home to me… amend" (Haines, 1916), and "reprove me… gladly retract" (Casaubon, 1634) — so an unqualified citation cannot be checked, and a reader who looks it up will conclude the quote is wrong. Cite as `Author, *Work*, §N (trans. Name, Year)`. This applies to the Stoic epigraphs (Marcus Aurelius, Epictetus, Seneca) in every digest, and to any classical, scriptural, or foreign-language source. Verify the wording against the **named** translation at source, and keep the quoted text verbatim, including archaic spelling. **Never paraphrase inside quotation marks:** if no direct rendering of the passage is available, either find one or drop the quotation marks and attribute the idea in prose. Note that several older Stoic epigraphs on the site are famous loose paraphrases ("You have power over your mind—not outside events") circulating without a source text; those must be labeled as paraphrases, not presented as translations.
- **An attribution naming an author the source does not name is a fabrication.** The URL rules above catch an invented link. They cannot catch an invented **name**: on 2026-09-19 the "best time to plant a tree" adage was credited to "O'Toole" with two correct, live links, and neither source contains that name — it is the surname of the researcher who runs Quote Investigator, not the saying's source. Every link check passed. **Before writing a name into an attribution, find that name in the source you are linking**, not in your memory of who investigates the topic. If the source lists candidates, use one of them or say the source is anonymous. A wrong attribution misleads a reader more than a missing one, because it looks checkable.
- **Do not attribute a rendering to a translator without testing it against that translation.** The same session found an epigraph credited to "George Long, 1862" that was in fact Elizabeth Carter's wording, and a Nietzsche line quoted in a familiar paraphrase that appears nowhere in the linked Ludovici translation. `Author, *Work*, §N (trans. Name, Year)` is only a citation if the words between the quotation marks are that translator's. Test the site's exact rendering as a substring of the named translation before writing the name (normalize whitespace first, per the rule above); if it does not match, either quote the rendering that does, or drop the translator's name and label the wording a paraphrase.
- **Every direct quotation must carry a resolvable source link in the piece's own citation apparatus.** Verified-at-source is an assertion; a URL is evidence, and a reader (or the next session) can check it after the fact. Record the link in the file's existing apparatus: the `## Sources` list in digests and essays, the footnote block in pieces that use footnotes, or inline for short-form posts. Three rules on what counts: (1) **the link must contain the quoted wording** — point at the specific translation, edition, or passage, never at a landing page, a publisher's catalog page, or an encyclopedia article *about* the work; (2) the link must be **live at publish time** (check for HTTP 200 — Gutenberg ebook pages, Wikisource book pages, and court/agency documents all qualify); verify the wording by **normalizing whitespace first** (`re.sub(r"\s+", " ", text)`): PDFs, HTML, and hard-wrapped plain text all break lines mid-sentence, so a literal substring test reports a false miss on a source that does contain the quotation (the Vaughan PDF of Carter's *Enchiridion* wraps "…in our control and\nothers not"). Extract PDF text with `pdftotext` before searching; (3) for a work where the quoted rendering exists in no linkable text, that is a finding, not a nuisance — either quote a rendering you can link (the `stoic-backgammon-summary.md` pattern, which quotes the sourced Long rendering alongside the paraphrase) or drop the quotation marks and attribute the idea in prose. A quotation whose wording cannot be linked should not appear as a quotation. **This is enforced:** `scripts/check-quotes.py` runs as a pre-deploy CI gate and fails the build on any attribution that names no translator (for a translated author) or has no URL-bearing line naming that author. Pre-rule quotations are listed in `scripts/quote-baseline.txt`, keyed by a hash of the quoted text — **editing one withdraws its exemption**, so the rule catches up as each file is next touched. Run `python3 scripts/check-quotes.py` before committing content; add `--online` to also fetch each link and confirm it really contains the quoted wording.
- **A quotation is a claim that these exact words appear at this address — including every detail inside it.** The 2026-10-04 Senate report quoted the name `"Daniel J. Sullivan Jr."`; the cited page says `Daniel J. Sullivan` and contains no `Jr.` anywhere, and every gate reported OK. Two facts made that invisible, both **measured** rather than assumed. First, `check-quotes.py --online` is **inert on a report**: it audits em-dash epigraphs (`"quote" — Author`), and a newspaper footnote is not that shape, so it scans such an article as *zero attributions* and verifies nothing. Second, a general "every quoted fragment must appear on a cited page" check is **unusable**: run against that same report it reported **70 of 169** fragments missing, because footnotes quote link *titles*, use ellipses (`"on top of $33 million ... bringing"`), and cite paywalled or JS-rendered pages an automated fetch cannot read — and a gate that fails correct reports is worse than none. So the mechanical guard is deliberately the **narrow, checkable** half: `scripts/check-quote-names.py --online` flags a quoted **name detail** — a middle initial (`First M. Last`) or a generational suffix (`Jr`, `Sr`, `II`, `III`, `IV`) — that appears on none of the pages the citing line links. On the corrected report it flags 0 of 2; on the injected defect, 1 of 1; across all published installments, nothing. It runs in the publishing gate set (`run_report_gates` in `scripts/publish-report.sh`), where a hit aborts the push. It is a floor, not the rule: the rule is that a name, initial, suffix, title, or figure inside quotation marks is **read off the fetched page and copied, never reconstructed**, and a quotation whose wording cannot be linked does not appear as a quotation. **The trigger is deliberately narrow, and the first corpus run proved why.** Wired into the weekly sweep on 2026-10-08, the gate's first full-corpus pass accused three published quotations of fabrication and all three were correct: the words are verbatim in the cited Project 2025 PDF (extracted with `pdftotext` to check), and the trigger had matched a bare Roman numeral in `Article II of the U.S. Constitution` and `In Pillar IV`. A numeral now counts only when the word in front of it is not a structural noun, `Jr`/`Sr` always count, and `TestQuoteNameRules` pins both directions. **Do not broaden it back:** a gate that fails a correct citation is worse than one that shows a human the sentence.
- **NEVER construct a URL. Fetch it, or do not cite it.** A URL may be written only after the page has actually been retrieved and confirmed to be the thing being cited. Do not build a URL from the pattern of a real one, do not infer a slug from a headline, and do not guess a date-and-slug from a story's publication date. This is the single most dangerous failure in the repo because the result is **invisible to every ordinary check**: the ID is real, the domain is right, the link returns HTTP 200, and the reader lands on an unrelated article. Three such fabrications shipped before this rule (found 2026-09-19): a "Trump's name removed from the Kennedy Center facade" citation that resolves to a story about pollinator gardens in Oklahoma; a *How Democracies Die* book link that resolves to a children's novel; and a New Republic "Peter Thiel and mimetic desire" article that resolves to a piece about campus consent laws. All three had correct IDs and invented slugs. **If a source cannot be retrieved, either cite it in prose without a link, replace it, or drop the claim.** An absent citation is honest; a plausible-looking wrong one is not.
- **A link's visible text must be the thing cited, never a placeholder like `text`, `here`, or `link`.** Write `["The Fight for the Senate Is a True Toss Up,"](url) September 23, 2026`, not `([text](url))`. The reader sees the anchor, so `[text]` tells them nothing about where the link goes. More seriously, `check-links.py --titles` catches this repo's most dangerous failure — a URL that returns 200 and serves an unrelated article — by comparing the citation's link text against the fetched page's own `<title>`, and a placeholder anchor leaves nothing to compare. **The entire Senate race series shipped with `[text]` anchors, so it had zero comparable citations and the wrong-page check could not see those reports at all** (found 2026-09-27). Anchors shorter than `MIN_HEADLINE_WORDS` are not compared either, so a two-word label is equally invisible. **This applies to every published post, not just the reports:** a further **36 published files** (16 summaries, 16 digests, 2 stoicism, 1 civics) carried `[text]`/`[here]` anchors, and were repaired on 2026-09-27. Two anchors are correct for the shapes that exist here — the work's own title for an epigraph (`[*Meditations* 4.18](url) (trans. George Long, 1862)`), and `on Amazon` for a buy link (`Buy it [on Amazon](url)`). Do **not** anchor an epigraph to the fetched page's `<title>`: Wikisource serves *Meditations* as `The Thoughts of the Emperor Marcus Aurelius Antoninus/Book IV`, so a work title either falls below `MIN_HEADLINE_WORDS` (inert) or would mismatch on every classical citation and fill the Monday titles report with false alarms. Enforced by `scripts/check-report-frontmatter.py`: `--file`/`--corpus` for report installments, **`--anchors-corpus` for every published post** (in CI).
- **A link that resolves to the wrong page is a fabrication.** `scripts/check-links.py --check` runs in the deploy workflow and rejects placeholder URLs (`[ID]`, `TODO`, `example.com`) and any URL recorded in `scripts/check-links-blocklist.txt` as proven to land somewhere other than the cited article. Run `python3 scripts/check-links.py --online` before publishing to fetch every cited URL and report what it actually finds; a `REDIRECT` verdict where the slug changed is the fabrication signature, and a `200` is not proof of correctness. Two blind spots in that gate were measured on 2026-09-25 and are now closed — both had been reporting OK on wrong links:
  - **A bot-challenge wall is not a live page.** ESPN answers a browser User-Agent with `202` and a ~2 KB AWS WAF interstitial (`x-amzn-waf-action: challenge`) for **every** URL, live or dead. Read as a 2xx that hid **three dead ESPN links** through a full-corpus sweep *and* a single-file sweep — the first agent-written Chiefs report cited two URLs that 404 (`.../preview/_/gameId=…`, `.../boxscore/_/gameId=…`; the live form uses a slash, `.../preview/_/gameId/…`). `probe()` now detects the challenge and **retries with no User-Agent at all**, which is the mode that makes ESPN answer truthfully — a real 404 for a bad URL, a 200 with a 130-480 KB body for a good one. That is also why `scripts/chiefs-report.py` sends no UA: it is the only header choice ESPN's wall does not intercept. A link that is challenged both ways is `UNVERIFIED` ("we could not look"), never `OK`.
  - **`200` from some hosts is not evidence the page is the one cited.** ESPN serves **200 for an invented story id** and lands the reader on an unrelated article: `.../story/_/id/99999999999/not-a-real-story` returns `200` with the title "Ranking the top 25 WNBA players in the playoffs". No status check can see that. `--online --titles` fetches each page's `<title>` and compares it against the citation's own link text, reporting a `TITLE MISMATCH` where they do not overlap. It is deliberately reported and **not** fatal (the comparison is a heuristic; a gate that fails a correct citation is worse than one that shows a human the sentence), but it is the only check in the repo that can catch the failure CLAUDE.md calls the most dangerous one here. `--file <path>` scopes the whole sweep to one article, which is what makes it usable on a brand-new file that no corpus scan can see yet.
- **There is no merchandising and no shop route.** `content/shop/`, `layouts/shop/`, `static/img/shop/` and the merchandise print masters were retired in full on 2026-09-19 (Philip: "No more merchandising"), along with the `Shop` entry in the main menu. Do not reintroduce a shop section, a product page, a marketplace link, or a `Shop` nav item without an explicit instruction to rebuild that surface. The credo is a statement, not a product line.
- **Any button whose text color differs from the site's link colors needs an explicit `:visited:hover` override.** `phbooks.css` carries a global `a:visited:hover { color: red }` (the intentional classic blue/red gallery-link hover — do not remove it). It out-specifies a plain `.<class>:hover` because it includes the `a` type selector, so it will repaint such a button's text invisible. This bug shipped twice on the old shop buttons before it was found.
- **One commit per publish.** The content file and its SESSION_STATE.md entry go in a single commit, pushed once. No follow-up "session state" commits after a content commit.
- **Post-commit SimpleBrain flow.** After the publish commit is pushed: (1) copy the published post to `~/SimpleBrain/raw/content/posts/<section>/` (resolves through the `~/SimpleBrain` symlink to `/Users/prh/Developer/SimpleBrain`); (2) translate it per `~/SimpleBrain/translate.md` — write the full article (frontmatter stripped, `# Title` heading) to `~/SimpleBrain/wiki/articles/<slug>.md` with a `---` + `Source: huffmanwrites.org/posts/<section>/<slug>/` footer, and add a `[Title](articles/<slug>.md)` line to the Recent Highlights section of `~/SimpleBrain/wiki/index.md` (prune the oldest highlight if the list grows past ~7). Use standard markdown links, never Obsidian `[[wikilinks]]`: Obsidian is not installed on this machine and `[[...]]` renders as literal text everywhere, including GitHub; (3) move the raw file to `~/SimpleBrain/archive/` (flat, never delete); (4) commit and push the SimpleBrain repo (`git -C ~/SimpleBrain commit` + push). The SimpleBrain repo is separate from huffmanwrites; its commits do not trigger the site deploy.
- **Gallery link hover colors** (`blue`/`red`) are intentional — do not suggest changing them.
- **`all-my-books.md`** is kept as an alternate entry point to `/books/` (renders via `book_catalog` shortcode). Do not delete.
- **Empty non-Constitution stubs** should be deleted. Constitution stubs are kept and written up.

## Scheduled jobs (launchd)

Twelve unattended jobs run from `scripts/` via launchd. Each is a `com.huffmanwrites.*.plist` (repo copy) installed to `~/Library/LaunchAgents/`, invoked through a `*-runner.sh`, with output in `~/Library/Logs/`. `scripts/check-plists.py` gates them in CI: a malformed plist fails silently (`launchctl bootstrap` does not always report it), so a schedule that never runs is the defect it exists to catch.

| Job | Schedule | What it does |
|---|---|---|
| `ollama-app` | At login (RunAtLoad) | Opens the Ollama app and verifies its server answered; the dependency every AI job calls |
| `docket-watch` | 07:30, 18:30 daily | Alerts on any new filing in the three watched dockets |
| `docket-weekly-report` | Saturdays 08:00 | **Publishes** the weekly docket report (first run 2026-10-03) |
| `senate-report` | Sundays 07:00 | **Publishes** the weekly Senate race report (self-disables after 2026-11-02) |
| `ninety-days-report` | 1st of each month | Drafts the bond and S&P ninety-day installments |
| `repair-plan` | Quarterly (Jan/Apr/Jul/Oct 1) | Revises the long-horizon repair plan |
| `site-audit` | Mondays 13:00 | Builds and crawls the live site for broken links and CSP drift |
| `wiki-check` | Mondays 13:30 | Audits and fixes the SimpleBrain wiki |
| `weekly-integrity` | Mondays 14:00 | Online link sweep + online quotation verification |
| `chiefs-weekly-report` | Tuesdays 18:30 | **Publishes** the weekly Chiefs report (in season only) |
| `weekly-satire` | Mondays 07:00 | **Publishes** the Weekly Satire series (2026-10-12 through 2026-11-02, then self-disables) |
| `daily-sitrep` | Every day 06:00 | **Publishes** the Global SITREP (2026-10-07, open-ended) |

Rules for these, learned by shipping the failures:

- **The weekly reports publish; the rest file drafts.** Philip, 2026-09-27: "publish weekly reports that have an exit code of 0 after passing all gates." Senate, docket, Chiefs, Weekly Satire and the daily SITREP write, verify, commit, push and mirror in one run. Ninety-days and repair-plan still file `draft: true` and leave the file uncommitted. **The difference is what a gate failure costs:** in a publishing job the gates are the only review the piece gets, so a failure **aborts the push**; in a drafting job it is a note for Philip.
- **A runner that runs the agent must run the verification itself.** The agent cannot execute the gates (they are deliberately absent from its allow-list), so a gate result in its summary is unverifiable. The runner runs the builds and the gates and puts the real exit codes in the log.
- **Two builds, always.** The production build excludes `draft: true`, so it says nothing about the draft the job just wrote. The second build uses `--buildDrafts --destination <tmp>` so the file is rendered and checked without leaving a draft page in `public/`, which deploys.
- **Publishing jobs must run `check-links.py --online --titles`, scoped with `--file`.** An offline-only gate set cannot see the failure CLAUDE.md calls the most dangerous one here — a link that resolves to the wrong page. `--titles` fetches each cited URL and compares the page's own `<title>` against the citation's link text, and it is the only check in the repo that can catch it. The drafting jobs deliberately left it out ("not in a job that should finish in minutes"); a job that publishes cannot.
- **`scripts/check-report-frontmatter.py` is the publication gate.** It requires `draft: false` and `featuredOnHome: true`, a date not ahead of the clock, the four hero fields resolving to real files, and the closing attribution — and `--hero-plate <basename>` pins a series to its plate. Every rule encodes a shipped failure, and `draft: true` is the one that matters most now these jobs publish: the commit and push succeed, every other gate reports OK, and the deploy carries nothing.
- **The publish tail lives once, in `scripts/publish-report.sh`.** Preflight guard, SESSION_STATE entry, commit, push, push verification and the SimpleBrain mirror are shared by all five publishing runners; a runner supplies only what is specific to its series. Three copies is how the `featuredOnHome` rule came to live in one skill and not another, which hid five reports from the home feed. **The runner writes the SESSION_STATE entry**, from the real gate results: the agent cannot run the gates, so an entry it authored could only assert them. **One line is an exception and it is deliberate:** the SimpleBrain bullet is written before the mirror runs, so it describes what the runner does and names the log rather than asserting the mirror succeeded. Its first version claimed "SimpleBrain synced … committed and pushed" unconditionally, and the SimpleBrain agent caught it on 2026-10-07 by reading the entry back and noticing the step it described had not yet run. Reordering the tail so the entry could report the outcome would change a path no dry run can exercise, so the shape is pinned by `test_the_entry_never_asserts_a_mirror_result_it_has_not_seen` instead.
- **`REPORT_DRY_RUN=1` exercises everything but the commit.** A pipeline that publishes unreviewed must be provable without being performed; `REPORT_SKIP_SIMPLEBRAIN=1` skips only the mirror. The Chiefs job's historical `CHIEFS_DRY_RUN` / `CHIEFS_SKIP_SIMPLEBRAIN` names still work.
- **Guard a start date with a non-zero-exit-free path.** A job installed before its first due date must `exit 0` and log why; exiting non-zero raises the failure alert every week and trains the alert into noise.
- **`StartCalendarInterval` takes a single dict for a LaunchAgent.** An array of dicts is a LaunchDaemon form and is silently ignored, so the job parses cleanly and never fires.
- **The docket registry is `check-docket.py`'s `CASES` map and nothing else.** Adding a case never means editing a runner or a plist. Both the watcher and the weekly report read the same registry, so a new docket appears in both.
- **Every AI job depends on the Ollama desktop app's server, and two things now keep it honest.** The eight jobs that call a model (`senate-report`, `docket-weekly-report`, `chiefs-weekly-report`, `ninety-days-report`, `weekly-satire`, `repair-plan`, `wiki-check`, `daily-sitrep`) set `ANTHROPIC_BASE_URL=http://localhost:11434`; that port is served by the **Ollama desktop app**. (1) `com.huffmanwrites.ollama-app` opens the app at login (`RunAtLoad`, `open -a /Applications/Ollama.app`, deliberately **no** `KeepAlive`), so the server is up before the 07:00 jobs run. (2) `scripts/ollama-probe.sh` (`ollama_require "$JOB" "$OUT_LOG"`, sourced by every one of the eight before its writer runs) fails loudly and alerts if the server is unreachable, so an app that quit or crashed is a one-line abort at the top of the log rather than a connection error mid-draft.
  - **Do not re-add the app's own macOS login item, and do not point this job at a server binary.** Both mistakes have shipped here. The app registers itself via `SMAppService` and can be added in System Settings; that enrolment was added on 2026-10-07 and verified enabled, then **removed by the app on its next start** — its log reads `removing login item /Applications/Ollama.app` at the moment the app launched (`updater_darwin.go`), and the registration (`2.com.electron.ollama`) is absent from `sfltool dumpbtm` afterwards. Note the app still reports `service is already enabled` at that same start, so its own status line is not evidence; read the BTM dump. A GUI setting the app clears on startup is not durable for an unattended publish, which is why the enrolment lives in a plist in git. And an earlier `com.huffmanwrites.ollama-serve` job ran `ollama serve` directly, which put a **second server on the port the app already serves**; it was retired the same day. `open -a` starts the app (one `ollama serve` either way) and can never run a server itself.
  - **The path that matters is `localhost`**, which resolves `::1` first on this machine, and the app's socket is dual-stack, so `localhost` and `127.0.0.1` both reach it.
  - **"Did Ollama start at login?" is answered by the log, not by looking.** `scripts/ollama-app-launch.sh` (which the job runs) opens the app and then polls `:11434/api/version`, writing `Ollama server reachable … after Ns` on success or raising the shared alert if it never answers. A bare `open -a` could not do this: it exits 0 the moment LaunchServices accepts the request, so a login where the app never came up looked identical to one where it did — the exact ambiguity that made the 2026-10-07 login unauditable. Two things also make the app easy to think absent, and both cost real time on 2026-10-07: it is a menu-bar-only app (`LSUIElement = 1`), so it has **no window, no Dock icon, and never appears in ⌘-Tab** — checking ⌘-Tab for it cannot succeed, by design — and macOS may relaunch it `hidden` after a restart, which `open -a` does not produce (`~/.ollama/logs/app*.log` and `sfltool dumpbtm`'s `Last Use` settle what actually happened).
- **Things to know before editing the Chiefs job:**
  - **The data is collected by a script, not by the agent.** `scripts/chiefs-report.py` writes a briefing pack (the week's game with both box scores and leaders, every scoring play, both injury reports, standings and seed list, season statistics, the next game with the feed's own odds and matchup projection, two weeks of tagged coverage with URLs). The writer reads the pack and is not permitted to recall a score. A pack failure is a hard stop.
  - **Its frontmatter used to be validated by that script** (`--validate`); those rules now live in `scripts/check-report-frontmatter.py`, shared with the other two publishing jobs, and `--validate` is a thin delegate. The rules moved rather than being copied because a second copy is how the two versions drift, and the drift is silent until a report ships wrong.
  - **The season guard reads the league's own published calendar**, not a hardcoded month range, so it rolls over by itself. Off season it exits 0 (a non-zero exit would alert every Tuesday for six months).
  - **ESPN's API refuses a browser User-Agent** (403 on all four endpoints used) and answers a default client. That is the opposite of every other script here and the reason `chiefs-report.py` sends no UA. Do not "normalize" it.
  - **ESPN fails open on an unknown season.** `standings?season=2027` returns 200 with the 2026 standings; `schedule?season=2027` returns an empty list and `requestedSeason: null`. `assert_season` refuses a payload that does not name the year asked for, because a writer handed one would produce a report about the wrong season with nothing in it looking wrong.
  - **`level=3` is required on the standings endpoint.** Without it the AFC node carries sixteen flat entries and **no** division children, so the division table and the seed list come back empty and those sections silently vanish from the pack.
- **Things to know before editing the Weekly Satire job:**
  - **It is the only writing job whose material is *selected*, not collected.** There is no briefing-pack script and there cannot be one, because the subject differs every week. The fabrication risk a pack removes is handled instead by the skill's fetch-before-cite rules (`skills/weekly-satire.md`) and by the gate set: the runner aborts the push on a dead link, a placeholder anchor, or a quoted name detail that appears on none of the pages the citing line links. If a future session wants to harden it, the lever is a collector that pre-fetches a candidate pool for the writer to select from, not a longer set of instructions.
  - **It self-disables on a date, in both directions.** `WEEKLY_SATIRE_IGNORE_GUARDS=1` runs it outside the 2026-10-12 / 2026-11-02 window so the pipeline can be exercised without publishing early or late; the scheduled run sets no such variable. The end guard is what makes "End the task 03NOV26" true — the last installment is Monday 2026-11-02 and every Monday after exits 0.
  - **One fixed hero plate, not a fresh image per run.** `114-weekly-satire_*`, pinned by `--plate 114-weekly-satire`, like the Senate/docket/Chiefs plates. Do not give an individual installment its own hero.
- **Things to know before editing the daily SITREP job:**
  - **It is the only job that publishes every day** (Philip, 2026-10-07: "I want to publish a weekly report every day of the week", resolved with him to one daily series rather than a new weekly series per empty weekday). At daily cadence a mistake is not wrong once, it is wrong seven times a week, and there is no review window: by the time a human could read an edition, tomorrow's is due. That is why its test class (`TestDailySitrep` in `scripts/test_gates.py`) asserts the wiring rather than the prose.
  - **The pack is a hard stop, and it is the whole anti-fabrication control.** `scripts/sitrep-pack.py` fetches the Federal Register, the CourtListener search API, the Treasury daily yield curve, FiscalData's debt-to-the-penny, CNBC's quote service, the BLS public API and Polymarket's Gamma API, and writes a briefing pack the writer reads. The writer is not permitted to recall a figure. A pack failure aborts the run; a *single source* failing is not a pack failure — the collector exits 0 and prints `SOURCE UNAVAILABLE` for that source, because a report with a stated gap is honest and a job that dies on a host hiccup produces nothing at all.
  - **One beat has no collector, by design, and there used to be two.** World affairs is fetched and cited by the writer, in the same way the Weekly Satire job works; the lever for hardening it is a wider collector, not a longer set of instructions. **The technology and AI beat was removed on 2026-10-07**, the day after the first edition shipped, when Philip read that risk stated plainly ("That risk concerns me. Let's eliminate the AI beat"). It had a prediction-market half and a fetched half, and the fetched half was the one place the writer chose what to assert with no collector behind the choice — so the beat went, and with it the `ai` and `technology` Polymarket tags, the pack's section 7, the skill's section and its `ai` tag. Removing an uncollected beat is the cheapest fix available and the first one to reach for; the skill's "A note for a future session" records it that way. **A future session must not reinstate it as an improvement.**
  - **It is excluded from the home feed and surfaced directly instead.** Seven installments a week would occupy all five Recent Posts slots permanently. `content/posts/sitrep/_index.md` cascades `hiddenInHomeList: true`, and `layouts/index.html` renders the current edition in its own block, selected on the same `featuredOnHome: true` flag the frontmatter gate requires — so the flag still means what it says. Do not "simplify" this by removing either half: without the cascade the feed is drowned, and without the block the series reaches no reader from the home page at all.
  - **One fixed hero plate.** `115-sitrep_*`, pinned by `--plate 115-sitrep`. Do not give an individual edition its own hero.

## Deployment

GitHub Pages, deployed automatically on push to `main` via `.github/workflows/hugo.yml`. The workflow installs Hugo 0.166.0 extended, builds with `hugo --gc --minify --baseURL "${{ steps.pages.outputs.base_url }}"`, and uploads `./public` as a Pages artifact. `static/CNAME` ensures the custom domain `huffmanwrites.org` is preserved.

To deploy from a detached worktree (e.g. Codex): `git push origin HEAD:main`.

## Newsletter sends

Digests are sent via the SendFox API using a token stored in the **login keychain** (`huffmanwrites-sendfox`), with `~/.secrets` (`SENDFOX_CLIENT_SECRET`) as the fallback — never a repo-local `.sendfox_token`. After a digest is sent, the corresponding file in `pending/` is moved to `pending/archive/` and a Hugo content page is created in `content/posts/digests/`. SendFox form submissions are whitelisted in the CSP `form-action` directive.
